# MAS — 移动自动化系统（Mobile Automation System）

在 Android 设备上**本地运行**的通用自动化工作流平台：可视化流程编辑（信号流语言）+ 后台虚拟屏执行 + 定时任务 + 自定义节点扩展。

无需 PC、无需模拟器。通过 Shizuku/Root 获得完整的系统级自动化能力。

## 特性

|  | 特性 | 说明 |
|---|---|---|
| 🧩 | **脚本工坊** | 可视化节点图编辑器 + **信号流流程语言**（见下） |
| ⚡ | **信号流语言** | 节点=函数，线=信号通道（顺序/是/非带二极管过滤）；合取/析取汇聚、循环终点、突发哨兵 |
| 🎨 | **自定义节点** | 用 JSON 模板定义自己的节点（执行/判定/控制，可带参数与执行命令） |
| 🖥 | **后台虚拟屏** | 目标应用在虚拟显示器中运行，不打扰前台；实时预览 + 触摸映射 + 触摸痕迹 |
| 🧰 | **虚拟坐标选取** | 暂停流程冻结画面，在预览上点选/画线校准坐标（解决寻路类反复识别场景） |
| ⏱ | **定时任务** | 按预设时间自动启动流程 |
| 🔗 | **配置绑定流程** | 后台任务配置绑定工坊流程，流程更新自动同步 |
| 📋 | **运行日志** | 全量执行日志、服务/应用状态监控 |

## 信号流流程语言

**核心模型**：节点=函数（执行动作/判定条件），线=带二极管的信号通道。

### 节点（函数）

| 分类 | 节点 | 语义 |
|---|---|---|
| 执行 | 流程信息/时间/点击/滑动/返回/输入 | 动作函数，完成后发「完成」信号；**=断路**（信号不穿过） |
| 判定 | 图像识别/应用状态/自定义判定 | 条件函数，输出真/假信号 |
| 控制 | 循环起点/循环终点 | 循环闭合 + 条件判定 + 超时保护 |
| 控制 | 合取（全部满足）/析取（任一满足） | 信号汇聚：判定结果经是/非线连入，全部/任一到达→输出 |
| 控制 | 突发 | 全局后台监听哨兵，命中→中断→应急区间 |

### 线（信号通道）

- **顺序线**：放行「完成」信号（执行节点之间）
- **是线**：只放行「真」信号（判定命中）
- **非线**：只放行「假」信号（判定未命中；与是线同款，黄色）
- 信号不匹配=**信号断**（下游不执行）

### 连线规则

- 执行节点：只能连顺序线（不产生判定信号；可直接连合取/析取作为完成条件）
- 判定节点：连是/非线；目标是合取/析取/循环终点时=**信号输入**（广播不跳转）
- 执行节点只能一条进线（多路汇聚必须经合取/析取）；循环终点最多一条进线

### 循环

```
循环起点 → 循环体 → 判定(是/非线) → 循环终点（绑定起点，否则🚫）
```
- **循环判定**：结果连入循环终点（或经合取/析取合并），连「是线」=真→继续循环，连「非线」=假→继续循环
- **超时保护**：可选，超时强制成功放行（防死循环）
- **等待直到**：时间节点可"直到某判定为真"再继续

### 突发

流程外的应急哨兵：独立 IMAGE 判定始终监听，命中→中断主流程→执行应急区间→回到继续点。**循环判定不能兼作突发判定**（角色互斥）。

## 快速上手

1. **脚本工坊**：新建流程 → 添加节点（执行/判定/控制）→ 连线 → 保存
2. **后台任务**：引用流程（自动新建配置）或 🔗 绑定流程（自动同步）
3. **开始任务**：FlowEngine 按信号流逻辑在虚拟屏执行，实时预览 + 日志

## 构建

```bash
# 常规构建
./gradlew assembleDebug

# 手机端（aarch64）打包（本仓库预置了手机打包环境脚本）
bash build_run.sh
```

**构建依赖**：本仓库不包含 `app/src/main/jniLibs/`（MaaCore 预编译 so，~130MB 二进制）。
构建前需放置 MaaCore arm64/x86_64 的 so 到 `app/src/main/jniLibs/`，来源：
- 上游 [Aliothmoon/MAA-Meow](https://github.com/Aliothmoon/MAA-Meow)（AGPL-3.0）的 MaaCore 组件
- 或从已安装的 APK 中提取
